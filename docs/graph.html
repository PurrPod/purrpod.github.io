Graph

Graph（任务图 / 工作流）是任务编排中枢：用节点 + 边描述一条完整的多步骤工作流。每个 Graph 是一个独立文件夹，由运行时引擎解析并按拓扑顺序执行。 A graph is the orchestration hub: a full multi-step workflow described as nodes and edges. Each graph is a folder that the runtime parses and executes in topological order. 

graphs/<graph-name>/    # 市场仓库中的单元
├── graph.json           # 图定义（必需）
└── asset/               # 静态资源：看板 html 等（可选）

文件夹名必须与 graph.json 里的 name 字段严格一致（CI 校验）。 The folder name must match the name field inside graph.json exactly; CI checks it.

顶层字段Top-level field 说明Notes
name 安装标识，必须与文件夹名一致Install id, identical to the folder name
description / description-zh 英文 / 中文描述（市场展示）English and Chinese descriptions for the market
version Graph 规范版本，当前 "2.0"Graph spec version, currently "2.0"
core 该图执行所用模型，缺省 openai:deepseek-v4-flashModel used to run the graph, default openai:deepseek-v4-flash
global_schema 全局输入变量的类型声明与必填校验，驱动前端表单与运行时校验；缺失或多余参数会把任务直接置为 ERROR。 Type declarations and required checks for the graph's inputs. Drives the front-end form and the runtime validation; missing or extra parameters put the task straight into ERROR.
nodes / edges 节点定义数组与连边定义数组Node and edge arrays
dashboard 看板地址：单个字符串，或多看板数组 [{ "name", "url" }] Dashboard URL, or an array of them: [{ "name", "url" }]

边与数据流映射Edges and data flow 

{ "source": "nd_input", "target": "nd_tpl",
  "sourceHandle": "prompt", "targetHandle": "prompt" }
  • source / target 是上游 / 下游节点 id，sourceHandle / targetHandle 是端口名（不写默认为 "default"）。同一节点可被多条边连入 / 连出，实现字段级精确映射。 source and target are node ids; the handles name the ports (defaulting to "default"). A node can be wired many-to-many, giving field-level mapping.
  • 端口分 static 与 dynamic；动态端口由 dynamic_rules 驱动（如 { "watch_config": "template", "method": "regex" } 按模板里的变量名生成）。 Ports are either static or dynamic; dynamic ones are driven by dynamic_rules, for example { "watch_config": "template", "method": "regex" } to derive ports from template variables.
  • 触发端口 trigger：未连线时该节点开局自动执行；连线后则等上游数据再执行。 The trigger port decides when a node fires: left unconnected, the node runs at the start; connected, it waits for upstream data.
  • 节点间流转的是带类型的信封（Envelope）；已废弃的旧节点类型在加载时会报错并提示改用 file_reader / string / agent_loop。 Values travel between nodes as typed envelopes. Removed node types fail loudly at load time and point you at file_reader, string, or agent_loop.

开发与提交Build & submit

  • 可视化编辑：前端 DAG 画布内置编辑与一键 JSON 导入/导出。 Visual editing: the front-end DAG canvas edits graphs and imports or exports the JSON in one click.
  • 保存 / 读取：GET/POST /api/graphs/{name}、GET /api/graphs/{name}/schema。 Save and load: GET/POST /api/graphs/{name} and GET /api/graphs/{name}/schema.
  • 运行：POST /api/tasks/run（后台异步），状态走 GET /api/tasks/{task_id}/state。 Run: POST /api/tasks/run is asynchronous; poll GET /api/tasks/{task_id}/state.
  • 提交：在 extension/graphs/graphs/<name>/ 提 PR；CI 校验文件夹名与 name 一致、描述字段非空，合并后自动并入全局 registry.json。 Submit: open a PR against extension/graphs/graphs/<name>/. CI verifies the name match and the description fields, and the merge updates the global registry.json.
