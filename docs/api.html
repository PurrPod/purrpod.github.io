下列接口覆盖 src/server 下的全部端点，并就地给出每个端点的参数、响应与调用示例。只描述当前接口，不含历史或兼容别名。 The endpoints below cover everything under src/server, and each one lists its parameters, response, and a call example inline. They describe the current API only, with no legacy or compatibility aliases.

通用约定Common conventions

  • 基地址：默认 http://127.0.0.1:8000，端口可用环境变量 PURRCAT_API_PORT 或 main.py --api-port 指定。 Base URL: http://127.0.0.1:8000 by default; override with PURRCAT_API_PORT or main.py --api-port.
  • 数据格式：除文件上传（multipart/form-data）与静态托管外，请求与响应均为 application/json。 Format: JSON in and out, except file uploads (multipart/form-data) and static hosting.
  • 鉴权：仅 ACP 网关（/acp/*）需要，通过请求头 X-PurrCat-Token 携带 ~/.purrcat/acp_token 的内容；其余接口无鉴权（本地优先）。 Auth: only the ACP gateway (/acp/*) needs it, via the X-PurrCat-Token header carrying the contents of ~/.purrcat/acp_token. Everything else is unauthenticated, local-first.
  • 错误：HTTP 状态码 + { "detail": "<reason>" }（FastAPI 默认错误体）。 Errors: an HTTP status plus { "detail": "<reason>" }, FastAPI's default body.
  • 异步语义：/api/chat、/api/chat/batch、/api/chat/compress-memory、/api/config/deploy/{item} 等为后台异步接口，立即返回受理态，实际进度走对应的轮询 / SSE 接口。 Async semantics: /api/chat, /api/chat/batch, /api/chat/compress-memory, and /api/config/deploy/{item} accept and return immediately; poll the matching status or SSE endpoint for progress.

/api/webmin · Minimal-mode plugin system

极简模式插件系统Minimal-mode plugin system/api/webmin

源码：src/server/api/webmin.py ｜ 前缀：/api/webmin ｜ 端点：9 个

极简模式（web-minimal）宿主为纯静态页面（ui/web-minimal），通过本路由获取插件清单、按需读取插件静态文件（热插拔）、持久化宿主配置，并转发插件自带后端的 RPC 调用。宿主专用，插件一般经 callAction 间接使用（见文末「极简宿主与插件的接入方式」）。

约定Conventions

  • 插件来源与优先级：用户插件（~/.purrcat/webmin-plugins，优先级最高）> 沙盒插件（{AGENT_VM_DIR}/ui-plugin）> 内置插件（ui/web-minimal/plugins/builtin，只读）。同名 id 先命中者生效。
  • 宿主配置持久化于 ~/.purrcat/settings.json 的 webminConfig，结构为 { "plugins": { plugin_id: config }, "rail": {...}, "active": {...} }。
  • 本文件只新增路由，不修改任何现有 /api/* 路由行为。
  • 所有 /api/webmin 响应经中间件附加 Cache-Control: no-store（便于热插拔与调试）。

返回当前已扫描到的全部插件列表。新增插件后无需重启，刷新页面即可感知。

请求Request

无请求参数。

{

    {
      "id": "builtin-history",

      "slot": "panel",
      "slotDef": { "type": "panel", "area": "panel" },

      "backend": { "kind": "npm" },

每条插件附：configSchema（插件自声明）与 config（webminConfig 中已存值，有效配置 = schema 默认值 ∪ config 覆盖）、builtin（是否位于内置根）、backend（是否自带后端，有 server/server.js 则为 { "kind": "npm" }，否则 null）；root（声明的期望位置）、origin（后端回填的实际所在根）、rootOk（两者是否一致）；dependency 归一化为 [{ "type", "id" }]（类型限定白名单：skill / plugin / mcp / agentloop / sensor / graph）；slot 归一化为字符串 id，完整语义见 slotDef。

极简宿主与插件的接入方式

两条通道

通道适用说明Description
A. callAction 动作总线插件 → 宿主（推荐）经 postMessage 封装，宿主统一收口（原生能力、坐标换算、配置注入）。见下
B. 同源 fetch('/api/...')插件直连后端（高级）插件 iframe 与宿主同源，可直接调用任意 /api/* 接口，稳定性自担

callAction 协议

插件侧（iframe）唯一通道是 postMessage，向后端发送动作请求：

var id = ++seq;
window.parent.postMessage(
  { type: 'callAction', id: id, actionId: 'state.get', payload: {} }, '*'
);

宿主 → 插件（插件侧 window.addEventListener('message', ...) 接收）：

消息含义Meaning
`{ type: 'callActionResult', id, ok, data \error }`
{ type: 'configApply', config }用户在设置面板改了配置 → 实时下发全量 config
{ type: 'event', event, data }宿主广播：host.unmount、host.nativeCover（{covered}）、layout.empty（{empty}）、session.switched、branch.switched、config.updated

actionId 清单

（完整 payload → data 契约见 ../plugins/ui-plugin.md；实现以宿主 ui/web-minimal/assets/host.js 的 dispatch 为准）

分类actionId
会话／对话chat.send、chat.sendBatch、chat.interrupt、chat.traceToSkill、sessions.list、sessions.new、session.switch、session.rename、session.delete、session.branch、requests.list、requests.resolve
配置config.get（payload {plugin_id}）、config.set、settings.meta、settings.open、settings.close
文件／数据dialog.files、dialog.folder、dialog.resolveFiles、dialog.pickWallpaper、ref.graphs
容器（float／modal 插件）slot.move、slot.close、slot.hide
插件自身plugin.delete、plugin.rpc（{plugin_id, handler, payload}）
内置浏览器（仅 Electron 主窗口）browser.available、browser.newTab、browser.closeTab、browser.navigate、browser.reload、browser.goBack、browser.goForward、browser.bounds、browser.hide、browser.locate、browser.pickStart、browser.pickEnd、browser.pickElement、browser.openExternal、browser.openUrl
其它state.get、session.setDraftParadigm、branch.select

约束

  • 插件只能引用插件目录内的文件；宿主的静态路由做了路径穿越校验。
  • 插件 id 冲突按 用户 > 沙盒 > 内置 生效；想改造内置插件请另起 id。
  • 宿主 CSS 变量不跨 iframe 继承，插件用 var(--wm-*, fallback) 自带兜底。
  • 新增插件或改动 plugin.json 后，用户按 Ctrl+R 刷新即可生效（无需重启应用）。

/api/terminal · Terminal WebSocket

终端 WebSocketTerminal WebSocket/api/terminal

源码：src/server/api/terminal.py ｜ 前缀：/api/terminal ｜ 端点：1 个

基于 PTY（伪终端）的终端桥接接口，让 PowerShell/bash 认为自己在跟真终端对话，从而启用 readline、退格、Tab 补全、颜色、提示符等交互特性。Windows 使用 pywinpty（VS Code/Jupyter 同款），*nix 使用标准库 pty + os.fork。

约定Conventions

  • 单条 WebSocket 长连接对应一个 PTY 子进程；连接断开即杀掉该进程及其子进程树。
  • 主程序退出（Ctrl+C / uvicorn shutdown）时会统一清理所有活跃终端子进程。
  • 终端工作目录优先为 AGENT_VM_DIR，创建失败时回退用户主目录。
WS /api/terminal/ws 终端 WebSocketTerminal WebSocket

建立终端桥接连接：接受连接后启动 PTY（交互 shell 或指定命令），双向转发输入输出。

请求Request

参数Parameter位置Location类型Type必填Required说明Description
cmdqueryQuerystring否No不传 → 启动交互 shell；传字符串 → 执行该命令（执行完保持可交互）

消息协议Message protocol

前端 → 服务端（文本帧）：

  • 普通文本：作为 stdin 原样写入 PTY。
  • 控制消息：以 \x00（NULL）开头，其后为 JSON。目前仅支持尺寸调整：
"\x00{\"type\":\"resize\",\"cols\":120,\"rows\":30}"

服务端 → 前端（文本帧）：

  • PTY 原始输出文本（含 ANSI 转义序列）。
  • 启动失败或运行异常时，以红色 ANSI 包裹的错误文本回传，例如 \r\n\x1b[31m[Failed to spawn] ...\x1b[0m\r\n；失败后连接关闭。

无独立 JSON 响应；交互数据全部经 WebSocket 文本帧双向流动。

示例Example

const ws = new WebSocket('ws://127.0.0.1:8000/api/terminal/ws?cmd=dir');
ws.onmessage = (e) => console.log(e.data);
ws.send('\x00{"type":"resize","cols":120,"rows":30}');
ws.send('echo hello\r');

静态托管与生命周期

  • 极简宿主静态托管：将 ui/web-minimal 目录以 StaticFiles（html=True）挂载到 /minimal（目录存在时）。访问 http://127.0.0.1:8000/minimal 即打开极简模式宿主页面。
