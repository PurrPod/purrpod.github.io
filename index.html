What's inside

Five commitments, one foundation.

From how information enters the agent, to how tasks execute, how memory is organised, and how capabilities expand — you orchestrate all of it the way you work.

00

Information-Driven Agent Design

The model decides capability; information decides direction.

  • UI plugin architecture. Fold your working context into UI panels — a click can communicate what a paragraph used to.
  • Orchestrated information flow. Describe the agent's execution as a configurable DAG and orchestrate the loop with a single yaml file; you decide when information gets injected.
  • Multi-layer hybrid memory. Short-term working memory, MEMORY.md, and PurrMemo's episodic, semantic, and knowledge-graph layers, injected in stages.
  • Sub-agents that share context. Their own branch id, model instance, and event loop — over one shared contextual foundation.

01

Everything Is Plugins

Beyond the kernel — capabilities, flows, and interfaces are all extensible.

  • Tools, skills, sensors, agent loops, workflows and UI panels all plug in or get replaced.
  • One yaml file configures information injection, tool-use checks, and loop-exit conditions.
  • Six extension types: skill, ui-plugin, mcp, agentloop, sensor, graph.

02

RSI Self-Evolution System

Not only using capabilities, but building, evaluating, and iterating them.

  • The agent builds its own plugins: Trace2Skill, MCP tool building, sensor building.
  • Generated skills ship with a SKILL.md and an evals.json set, and must pass the built-in evaluator.
  • Hot reload, standalone HTML evaluation reports, and an iteration archive that can roll back.

03

Secure Self-Hosting

The agent has its own workspace; your host machine is still yours to control.

  • Commands and files live in a dedicated Docker container with persistent workspace and logs.
  • Imports are size- and path-validated; exports can trigger a Git snapshot for audit.
  • GOAL.md plus a heartbeat cycle lets the agent patrol and report while idle.

04

Efficient Context & Tool Management

Reduce unnecessary tool information; keep a stable long-session cache.

  • Key manager binds a session to one key, keeping the long-session prefix cache intact.
  • Tools and skills are stored then retrieved on demand — an attention problem turned into a retrieval problem.
  • Workflows pass node results as structured data, cutting repeated restatement between agents.

    Quickstart

    Install PurrCat

    Three steps from a clean machine: install PurrCat, launch the desktop app, and make it yours.

    1 Install PurrCat
    Install via

    Run in your terminal, then follow the prompts.

    $ curl -fsSL https://raw.githubusercontent.com/PurrPod/purrcat/main/install.sh | bash

    Run in PowerShell. Docker Desktop must be launched once afterwards to finish setup.

    > irm https://raw.githubusercontent.com/PurrPod/purrcat/main/install.ps1 | iex

    Prefer to read every line first? Clone the repository and run the installer yourself.

    $ git clone https://github.com/PurrPod/purrcat ~/purrcat
    What the script does

    It checks for and installs the required prerequisites, clones the source to ~/purrcat, installs the project dependencies, and registers a global purrcat command.

    Windows: launch Docker Desktop once after installation to complete setup and accept its agreement. The Windows flow is well tested; macOS and Linux have more limited coverage.

    2 Launch the desktop app

    Start the Electron desktop app, then confirm the API is listening.

    01 Start the desktop app

    $ purrcat desktop start

    02 Pin the API port

    The API uses port 8000 by default and quietly moves to the next free port when it is taken. To pin one instead:

    $ PURRCAT_API_PORT=8123 purrcat desktop start
